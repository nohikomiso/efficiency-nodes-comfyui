# Efficiency Nodes for ComfyUI (BREAK Support Custom Fork)

本リポジトリは、[jags111/efficiency-nodes-comfyui](https://github.com/jags111/efficiency-nodes-comfyui) をベースとした個人開発用のカスタムフォークです。複数キャラクター（マルチキャラクター）生成時における推論の安定化とプロンプト分離を目的としたコアロジックの改修が含まれています。

## 1. 開発の背景と課題

特定のワークフロー（主に Efficiency Nodes をメインパイプラインとして使用する構成）において、2人以上のキャラクターを同時に生成する際、プロンプトの特徴が混入・干渉（ブリード）する問題が頻発していました。
この問題の解決には、Automatic1111 WebUI (A1111) に実装されているコンテキスト分割機能（`BREAK` 構文）と同等の処理が必須となります。

しかし、当時の環境下において以下の課題が存在しました。
*   既存の `BREAK` 処理プロンプトノードは第三者による独立した実装しか存在せず、Efficiency Nodes の高度なエンコードパイプラインと接続した際に意図した挙動を示さないケースや、不具合が多発した。
*   参考に用いた既存の ComfyUI 用 `BREAK` 実装は、A1111における厳密なトークン分離やパディング処理（Padding）の水準に達しておらず、生成結果が不安定であった。

本フォークは、これらの課題を抜本的に解決するため、Efficiency Nodes のエンコード・デノイズ処理の最深部に、A1111仕様に準拠した厳密な `BREAK` 解析処理を直接組み込むことを目的として開発・微調整されています。

## 2. 技術的な主な改修内容

全体で約6,000行に及ぶコードの追加・再構築・リファクタリングを実施しています。

### 2.1. プロンプト分割パイプラインの統合 (`efficiency_nodes.py`, `bnk_adv_encode.py`)
*   **BREAK構文のネイティブ実装**
    テキストエンコーディング処理（`advanced_encode` 系）の内部プロセスに、`BREAK` キーワードをフックとした文章のチャンク分割処理を統合しました。
    分割された各コンテキストチャンクに対して適正な不要トークンのパディング（Padding）とベクトル（Conditioning）の合成を行い、A1111の振る舞いと等価な厳密な特徴量の分離を実現しています。
*   **リファクタリング**
    開発初期段階においてトークン分離やパディングの挙動検証のために独自に作成したテスト用・検証用スクリプト（`verify_break.py` 等）は、コアロジックへのネイティブ統合が完了したため不要と判断し削除・クリーンアップしています。

### 2.2. サンプリングおよびCFGデノイズ精度の最適化 (`bnk_tiled_samplers.py`, `smZ_cfg_denoiser.py`)
*   分割された複雑な Conditioning データ（ポジティブ/ネガティブ）を正確に評価するため、CFG（Conditioning Free Guidance）計算処理やノイズ加算プロセス（`calc_cond_uncond_batch`, `prepare_noise`等）の挙動を調整しました。
*   複数キャラクター生成時に発生しやすい乱数（RNGソース）のブレやアーティファクトを抑制するため、約800行のデノイザー関連処理の改修および微調整を実施しています。

### 2.3. 本家最新修正の統合 (Selected Upstream Improvements)
特定の「Copilot（実験的ブランチ）」から、本フォークの安定性を向上させるための最新修正を選択的に取り込みました。
*   **Seedコントロールの改善 (`js/seedcontrol.js`)**: シード値が `-1` の場合にUIを上書きしないよう変更し、再現性を向上。
*   **レイアウト安定化 (`js/widgethider.js`)**: ウィジェット高さの動的計算を導入し、ズームやフォント変更による表示崩れを解消。
*   **CFGデノイザーの呼出最適化 (`efficiency_nodes.py`)**: 旧 `SDKSampler` による直接置換を廃止し、`register_hooks()` による最新の整合性確保方式へ刷新しました。

### 2.4. 最新パッケージ管理環境 (`uv`) への対応
*   Python 3.13 / PyTorch 2.12 (CUDA 13.0) などの最新実行環境において、依存関係を厳密に解決するためのマニフェストファイル（`uv.lock`）を追加し、再現性と安全性を担保しています。

## 3. 運用上の留意点

本フォークは特定のニーズ（複数キャラクター生成の安定化）および特定のローカル実行環境に向けて極限まで微調整された技術検証用のブランチ（`feat/break-support`）です。
公式の上流リポジトリ（upstream）とはコードベースが大きく乖離しているため、上流からの直接的な `git merge` または `git pull` は意図しない競合（コンフリクト）を引き起こす可能性があります。全自動更新ツール等を使用する際は、本リポジトリが保護対象となっている構成での運用を推奨します。
